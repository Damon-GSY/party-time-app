# Party planner bug fixes implementation plan

**Goal:** Fix the five verified data/state defects without changing the visual design.

**Architecture:** Keep the web preview local and in-memory, but key event records by event ID and votes by participant ID. Reuse the mini-program's pagination, user-info and expiry contracts rather than adding competing state.

**Tech Stack:** Vanilla browser JavaScript, WeChat mini-program JavaScript, Node test runner.

## 1. Preview data isolation and identity (primary agent)

- Modify `preview.html`; add `tests/preview-state.test.js`.
- Write failing original-script/handler tests for event switching, creation retention, and nickname changes.
- Replace title-only navigation with an event registry and stable current participant ID. Render created events as reachable homepage entries. Restore the current participant's saved selection when re-entering an event.
- Verify count updates, same-nickname separation, event switch isolation and share title.

## 2. Mini-program defects (native implementation agent)

- Modify `miniprogram/pages/history/history.js`, `miniprogram/utils/user.js` and related shared logic for complete event pagination.
- Synchronize nickname changes with the global profile through the existing user-info update pathway.
- Modify `miniprogram/pages/poster/poster.js` to derive status from expiry.
- Add failing tests for more than 50 mixed records, user rename/profile refresh, and expired/future/permanent poster status; implement and rerun.

## 3. Acceptance and review

- Run `node --test tests/*.test.js`; preserve the 47-test baseline.
- Independently review specification coverage, then correctness/regression risk.
- Use a real browser for create → type nickname → select → submit → rename → resubmit → switch event → return and restore. Check mobile layout and keyboard operation.
- Record verified limits: preview is not a multiplayer backend; native runtime validation uses simulated WeChat APIs unless a real device is available.
- Commit reviewed scoped changes after verification; do not push or deploy.
